# Техническая документация
## Универсальный ИИ-ассистент для сайта ekt.kz

Версия: 2.0 (MVP для HACKALEM AI)  
Целевая модель: `gpt-5.6-luna`  
Дата: 23.09.2026

## 1. Назначение системы

Система представляет собой чат-ассистента для покупателей ekt.kz. Ассистент понимает текст, фотографии и файлы, ищет электротехнические товары в каталоге партнёра, сообщает подтверждённые характеристики и остатки, предлагает совместимые замены, отвечает по условиям покупки и добавляет товар в корзину только после явного подтверждения клиента.

Решение универсально для электротехнической номенклатуры: автоматов и УЗО, контакторов, реле, кабеля и провода, розеток и выключателей, светильников, ламп, щитов, корпусов, клемм, датчиков, источников питания, инструмента, расходников и других категорий каталога. Логика аналогов не должна быть привязана к одной категории.

Локальная LLM, fine-tuning и отдельная ML-модель не используются. Интеллектуальные операции выполняет `gpt-5.6-luna`, а поиск, проверка данных, ранжирование и изменение корзины выполняет сервер приложения.

## 2. Пользовательские сценарии

1. Клиент пишет артикул, название или описание нужной детали. Ассистент находит товар в каталоге и показывает цену, наличие, характеристики, сертификаты и ссылку на карточку.
2. Клиент отправляет фото маркировки, упаковки или самой детали. Модель извлекает читаемые артикул, бренд, серию и параметры; сервер подтверждает результат по API каталога.
3. Клиент отправляет PDF, DOCX или XLSX со спецификацией. Ассистент извлекает артикулы и количества, после чего проверяет их через каталог.
4. Товара нет или клиент просит замену. Сервер подбирает универсальные аналоги из каталога и, при необходимости, через web search. Ассистент показывает совпадения, отличия, источник и уровень уверенности.
5. Клиент спрашивает об оплате, доставке или минимальной партии. Ответ берётся из утверждённого справочника условий, а не придумывается моделью.
6. Клиент просит добавить товар. Ассистент сначала показывает предложение. Изменение корзины выполняется только после явного подтверждения вроде «да, добавь 2 штуки».

## 3. Требования и ограничения

### Обязательно

- поиск по артикулу, названию, бренду, категории и характеристикам;
- обработка изображений и файлов;
- свежая проверка цены и остатка через API перед показом и перед добавлением;
- минимум один доступный кандидат при наличии подходящего аналога;
- объяснение, почему аналог подходит, и явное перечисление отличий;
- ответ на вопросы об условиях покупки;
- ссылка на карточку товара и актуальную корзину;
- поддержка мобильной и десктопной версии чата;
- все операции с корзиной защищены сервером и требуют подтверждения.

### Запрещено

- выдумывать цену, остаток, характеристики, сертификаты, совместимость или условия;
- считать товар полным аналогом при несовпадении критичного параметра;
- менять корзину после обычной фразы «интересует товар» без подтверждения;
- добавлять количество выше актуального остатка;
- передавать или хранить платёжные данные;
- использовать web search как замену официальным данным ekt.kz о цене и остатках.

## 4. Источники данных

### 4.1. Каталог ekt.kz — главный источник

Доступ выполняется с backend по Basic Auth. Секреты не попадают во frontend, репозиторий, ответы API, логи и документацию.

```text
GET https://ekt.kz/api/products
GET https://ekt.kz/api/products?page={page}
GET https://ekt.kz/api/products/detail?id={id}
```

Конфигурация:

```env
EKT_API_BASE_URL=https://ekt.kz/api
EKT_API_USER=<secret>
EKT_API_PASSWORD=<secret>
```

Список товаров загружается постранично. Детальная карточка запрашивается лениво и повторно перед критичными действиями. Реальные имена полей должны определяться адаптером по фактическому JSON-ответу; приложение не должно жёстко полагаться на одну форму вложенного `properties`.

Нормализованная внутренняя модель:

```json
{
  "id": "515291",
  "article": "...",
  "name": "...",
  "brand": "...",
  "category": "...",
  "description": "...",
  "price": 0,
  "quantity": 0,
  "stores": [{"name": "...", "quantity": 0}],
  "attributes": {"key": "value"},
  "certificates": [{"name": "...", "url": "..."}],
  "product_url": "https://ekt.kz/...",
  "source": "ekt_catalog"
}
```

`quantity`, цена и сертификаты передаются модели только после нормализации и проверки схемы. Если поле отсутствует, значение считается неизвестным, а не равным нулю.

### 4.2. Интернет — дополнительный источник аналогов

Web search используется только когда:

- товар не найден в каталоге;
- в каталоге нет подходящей замены;
- нужно найти страницу производителя, datasheet или рыночные варианты по точной маркировке.

Поиск выполняется через web search tool Responses API либо отдельным серверным поисковым провайдером. Для каждого внешнего результата сохраняются URL, название источника и извлечённые параметры. Ассистент обязан обозначать такой результат как «внешний вариант» и не утверждать его наличие или цену на ekt.kz.

Перед рекомендацией внешней замены проверяются: категория, назначение, электрические и механические параметры, размеры, способ монтажа, совместимость аксессуаров и нормативные ограничения. Если параметр неизвестен, результат помечается как «требует проверки менеджером».

### 4.3. Условия покупки

Пока отдельного API нет, используется серверный файл конфигурации `purchase_conditions.json`, утверждённый партнёром. Если справочник не заполнен, ассистент сообщает, что не может подтвердить условие, и предлагает связаться с менеджером.

## 5. Архитектура

```text
Web Chat (desktop/mobile)
        |
        v
Backend API / Session Manager
        |
        +-- OpenAI Responses API (gpt-5.6-luna)
        |     +-- image input / file input
        |     +-- function calling
        |     +-- web search (только для внешних аналогов)
        |
        +-- EKT Catalog Client (Basic Auth)
        +-- Catalog Cache / Normalizer
        +-- Universal Similarity Engine
        +-- Purchase Conditions Provider
        +-- Cart Adapter
        +-- Audit and Security Layer
```

Модель не получает Basic Auth и не обращается к ekt.kz напрямую. Она вызывает только описанные backend tools. Backend является единственным компонентом, который может читать каталог и менять корзину.

## 6. OpenAI API

Целевая модель — `gpt-5.6-luna`. Она принимает текст и изображения, поддерживает Responses API, function calling, structured outputs и web search. Основной цикл:

1. backend принимает сообщение и безопасно обрабатывает вложения;
2. отправляет модели текст, изображения/файлы и список tools;
3. получает вызов функции;
4. выполняет функцию на сервере и валидирует результат;
5. возвращает результат модели;
6. выдаёт пользователю ответ или выполняет следующий вызов.

Официальные ссылки: [модель GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create), [function calling](https://developers.openai.com/api/docs/guides/function-calling), [изображения и vision](https://developers.openai.com/api/docs/guides/images-vision), [файлы](https://developers.openai.com/api/docs/guides/file-inputs).

Пример переменных окружения:

```env
OPENAI_API_KEY=<secret>
OPENAI_MODEL=gpt-5.6-luna
OPENAI_REASONING_EFFORT=low
CATALOG_CACHE_TTL_SECONDS=1800
DETAIL_CACHE_TTL_SECONDS=300
MAX_UPLOAD_MB=20
```

Для ответа с фиксированной структурой применяются Structured Outputs. Для действий используются function tools с JSON Schema, а не JSON, написанный моделью в обычном тексте.

## 7. Инструменты ассистента

Минимальный набор backend tools:

```text
extract_product_identifiers
find_products
get_product_details
find_catalog_analogs
search_external_analogs
get_purchase_conditions
prepare_cart_addition
confirm_add_to_cart
get_cart
```

### `find_products`

Вход: `query`, `article`, `brand`, `category`, `attributes`. Поиск выполняется в порядке: точный артикул/штрихкод, нормализованный артикул поставщика, название и бренд, затем набор характеристик. Возвращается список кандидатов с причиной совпадения.

### `get_product_details`

Получает свежую карточку `/products/detail?id=...`, нормализует цену, остаток, склады, характеристики, сертификаты и URL. Для ответа о наличии используется только свежий результат или результат с коротким TTL.

### `find_catalog_analogs`

Получает исходный товар и извлечённые требования пользователя, затем возвращает доступные товары каталога с оценкой совместимости. Ранжирование выполняется кодом, а не моделью.

### `search_external_analogs`

Ищет по точным идентификаторам и техническим параметрам во внешних источниках. Возвращает URL и найденные факты, но не сообщает наличие или цену ekt.kz.

### `prepare_cart_addition`

Создаёт предварительное предложение:

```json
{
  "product_id": "515291",
  "quantity": 2,
  "price_at_proposal": 64920,
  "available_quantity": 23,
  "requires_confirmation": true
}
```

Функция ничего не меняет в корзине.

### `confirm_add_to_cart`

Вызывается только когда сервер определил явное подтверждение и существует актуальное незавершённое предложение. Повторно получает остаток, проверяет количество, вызывает доступный cart endpoint/адаптер, затем получает актуальную корзину. Если официального endpoint добавления пока нет, используется демонстрационный session-based adapter; это должно быть явно обозначено в README и демо.

## 8. Универсальный поиск аналогов

### 8.1. Нормализация

Перед сравнением backend приводит данные к единому виду:

- регистр, пробелы, дефисы и разделители;
- русские/латинские варианты обозначений;
- единицы измерения (В, А, мм, мм², Вт, кВт, °C, Гц);
- числа с запятой и точкой;
- синонимы (`кол-во полюсов` = `poles`, `степень защиты` = `ip`);
- диапазоны, значения «от/до» и перечисления;
- бренды, серии, артикулы и штрихкоды.

Неизвестный параметр хранится как `unknown`, а не как `0`, `false` или «подходит».

### 8.2. Динамический профиль категории

Система сначала определяет категорию и формирует профиль требований из характеристик товара, каталога и запроса пользователя. Фиксированный профиль автоматического выключателя не используется.

Примеры профилей:

| Категория | Возможные критичные параметры |
|---|---|
| Выключатели, УЗО | ток, напряжение, полюса, характеристика, отключающая способность, тип защиты |
| Кабель и провод | материал, число жил, сечение, напряжение, изоляция, длина, тип прокладки |
| Контакторы и реле | ток, напряжение катушки, число контактов, AC/DC, категория применения |
| Светильники и лампы | мощность, световой поток, цветовая температура, цоколь, IP, напряжение, размеры |
| Розетки, выключатели | серия, монтаж, число постов, ток/напряжение, IP, цвет, механизм |
| Блоки питания | вход/выход, напряжение, ток/мощность, тип корпуса, монтаж, IP |
| Щиты и корпуса | размеры, материал, IP, монтаж, число модулей, наличие панели |
| Клеммы и аксессуары | сечение, ток, напряжение, тип подключения, совместимая серия |

Если категория новая, система использует все доступные пары `ключ-значение`, выделяет параметры, названные пользователем, и снижает уверенность при неизвестной критичности. Профили можно расширять конфигурацией без изменения LLM.

### 8.3. Оценка кандидата

Общая оценка не заменяет инженерную проверку:

```text
score = 0.35 * critical_match
      + 0.25 * functional_match
      + 0.15 * dimensional_match
      + 0.10 * category_match
      + 0.05 * brand_or_series_match
      + 0.05 * availability
      + 0.05 * price_similarity
```

Вес критичных параметров задаётся профилем категории. Несовпадение параметра, который пользователь явно указал как обязательный, исключает кандидата. Товар с неизвестным критичным параметром не может быть назван полным аналогом.

Результат:

```json
{
  "kind": "catalog_analog",
  "product_id": "...",
  "score": 0.87,
  "match": ["категория", "напряжение", "сечение"],
  "differences": ["длина 50 м вместо 100 м"],
  "unknown": [],
  "quantity": 8,
  "recommendation": "possible_alternative"
}
```

Формулировки: `полный аналог` — только при совпадении всех известных критичных параметров; `возможная альтернатива` — при отличиях; `требует проверки` — при неизвестном критичном параметре.

## 9. Фото и документы

Фотография передаётся как `input_image` с `detail: high` для мелкой маркировки. Модель извлекает только наблюдаемые данные:

```json
{
  "article": null,
  "barcode": null,
  "brand": null,
  "model": null,
  "category": null,
  "attributes": {},
  "unreadable_fields": [],
  "confidence": 0.0
}
```

Если маркировка не читается или уверенность ниже 0.65, ассистент просит более резкое фото и не делает точного вывода. Визуально похожий объект нельзя считать найденным товаром без проверки каталога.

Поддерживаемые типы: JPEG/PNG, PDF, DOCX, XLSX. До передачи в OpenAI выполняются ограничение размера, проверка MIME, антивирусная проверка и удаление временного файла по политике хранения. Из таблиц и документов извлекаются артикулы, количества и параметры; каждое значение подтверждается через каталог.

## 10. Чат, подтверждение и корзина

Состояние сессии:

```text
session_id
messages
last_candidates
pending_cart_action
pending_quantity
confirmation_status
```

Состояния корзины:

```text
NONE -> PROPOSAL_SHOWN -> WAITING_CONFIRMATION
WAITING_CONFIRMATION -> CONFIRMED -> COMPLETED | FAILED
```

Подтверждение действительно только для конкретного товара и количества из последнего предложения. Фраза «да» без контекста не должна изменять корзину. После успешного добавления возвращается ссылка на актуальную корзину. При изменении остатка клиенту показывается новое доступное количество и запрашивается новое подтверждение.

```text

Используй только факты из backend tools и явно предоставленных источников.
Не придумывай цену, остаток, характеристики, сертификаты, ссылки и условия покупки.
Каталог ekt.kz — источник истины для цены и наличия.
Внешние сайты используй только для поиска возможных аналогов или документации;
всегда показывай внешний источник и не утверждай наличие на ekt.kz.
Для любого аналога перечисляй совпадения, отличия и неизвестные параметры.
Не называй товар полным аналогом при несовпадении критичного параметра.
Перед изменением корзины покажи товар и количество и получи явное подтверждение.
Если данных недостаточно, честно сообщи об этом и задай уточняющий вопрос.
```

## 12. Безопасность и наблюдаемость

- Basic Auth ekt.kz и `OPENAI_API_KEY` хранятся только в переменных окружения или secret manager;
- запросы к API имеют timeout, ограничение повторов и валидацию схемы;
- пользовательский HTML экранируется;
- web search URL и файлы проверяются перед показом;
- персональные данные и содержимое документов не пишутся в обычные логи;
- cart tools требуют серверной авторизации и идемпотентного `operation_id`;
- в журнале аудита сохраняются `session_id`, tool, product_id, результат и время без секретов;
- ошибки каталога или OpenAI не приводят к выдуманному ответу.

## 13. Приёмочные тесты

1. Точный артикул: найден корректный товар, свежая цена, остаток и URL.
2. Общий запрос: найдены кандидаты по названию и характеристикам.
3. Товар с нулевым остатком: предложен доступный аналог с совпадениями и отличиями.
4. Фото с маркировкой: идентификатор извлечён и подтверждён API; при плохом фото задан уточняющий вопрос.
5. PDF/DOCX/XLSX: извлечены артикулы и количества, данные проверены каталогом.
6. Универсальность: тесты проведены минимум на выключателе, кабеле, светильнике, контакторе и блоке питания.
7. Внешний аналог: показан источник, параметры и предупреждение о необходимости проверки.
8. Условия покупки: ответ взят из справочника, неподтверждённые сведения не добавлены.
9. Без подтверждения: корзина не изменилась.
10. С подтверждением: остаток запрошен повторно, количество не превышено, возвращена ссылка на корзину.
11. Конкурентное добавление: при изменившемся остатке операция отклонена или скорректирована через новое подтверждение.

## 14. Этапы разработки

1. Создать backend, `.env.example` и безопасную конфигурацию.
2. Реализовать EKT API client, постраничную загрузку и нормализацию JSON.
3. Реализовать поиск по индексу каталога и кэш с TTL.
4. Подключить `gpt-5.6-luna` через Responses API.
5. Добавить tools, structured extraction фото/файлов и сессионный контекст.
6. Реализовать динамические профили категорий и универсальный similarity engine.
7. Добавить web search для внешних аналогов с сохранением источников.
8. Добавить справочник условий и CartAdapter с подтверждением.
9. Провести приёмочные тесты и негативные тесты безопасности.
10. Подготовить README, `.env.example`, архитектурную схему и демонстрацию.

## 15. Ограничения MVP

Предоставленные endpoint’ы описывают каталог и детали товара, но не подтверждают наличие API для изменения корзины, поиска сертификатов, условий покупки или полнотекстового поиска. Поэтому до получения официальной интеграции:

- каталог индексируется локальным backend-кэшем;
- сертификаты показываются только если они есть в detail API;
- условия берутся из конфигурационного справочника;
- добавление в корзину реализуется через адаптер, а не через выдуманный endpoint;
- внешние аналоги помечаются как внешние и не смешиваются с подтверждёнными товарами ekt.kz.
